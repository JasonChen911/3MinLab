# 活动实验室 · 通用活动策划平台

一句话描述活动 → 需求理解与澄清 → 生成含 12 个模块的可执行方案。
覆盖校园、学术、体育、公益、商业、创业、文艺、教育、招聘、社交与通用场景；未预设的活动类型也会走同一套框架生成，而不是套模板。

基本流程完全离线可用；DeepSeek 只作为「补充建议 / 追问」的增强层，需要网络与 API Key。

## 启动

建议 Node.js 24（本项目在 24 / 26 上验证）。

```bash
npm install
npm run dev     # 前端 5173 + AI 代理 8787
```

其他脚本：

```bash
npm test        # vitest（前端规则）+ node --test（服务端）
npm run build   # tsc + vite build
npm start       # 生产模式：托管 dist 并提供 /api
```

## 架构

```
配置层  src/data/taxonomy.ts    27 类活动 / 11 大类族 / 12 模块权重
        src/data/knowledge.ts   族级知识（议程·预算结构·角色·风险·KPI·渠道·合规）
                                + 类型级覆盖（只写差异）
引擎层  src/rules/intake.ts     自由文本 → 结构化需求 + 缺口提问 + 显式假设
        src/rules/generator.ts  需求 + 配置 → 12 模块方案（纯函数）
        src/rules/budget.ts     预算按结构切分，分项之和恒等于总额
        src/rules/export.ts     Markdown / 招募文案导出
表现层  src/App.tsx             输入屏 / 方案工作台
        src/components/*        BriefPanel、PlanView、BlockView、AiAssist…
服务端  server/index.mjs        静态托管 + /api/ai/*
```

**核心约束：引擎不认识任何具体活动类型。** 所有差异都来自配置，新增类型不需要改 `generator.ts`。

### 新增一种活动

1. 在 `src/data/taxonomy.ts` 的 `CATEGORIES` 里加一条：

```ts
{
  id: 'community-market',
  label: '社区市集',
  family: 'charity',            // 决定默认议程/预算/角色/风险
  keywords: ['市集', '跳蚤市场', '集市'],
  summary: '摊位、动线与邻里参与是重点',
  defaultPeople: 300, defaultBudget: 8000,
  defaultDuration: 240, defaultVenue: 'outdoor',
  defaultAudience: '社区居民与摊主',
  emphasis: { logistics: 'key', program: 'key' },  // 覆盖族默认权重
}
```

2. （可选）在 `src/data/knowledge.ts` 的 `CATEGORY_KNOWLEDGE` 里只写和族默认不一样的部分：
`agenda`、`budget`、`roles`、`risks`、`kpis`、`resources`、`interactions`、`notes`。

改完即可用，界面下拉、识别关键词、权重与全部 12 个模块自动生效。

### 模块权重

`key` 重点（内容全量 + 重点提示）、`normal` 常规、`brief` 简要（只留最关键两块，时间线/预算/人员表不裁剪）。
界面按权重显示徽标，侧栏高亮重点模块。

### 需求理解与假设

`intake.ts` 从文本里抽取人数、预算、日期、时长、场地、类型、人群与目标；缺失项用同类活动的常见值填充，并写入 `brief.assumptions`，界面逐条标注「假设」。
只对仍为假设的关键字段提问，优先级：人数 → 预算 → 日期 → 时长 → 场地 → 目标，每轮最多 3 个问题。

## 界面

两屏结构，视觉与组件沿用原有设计系统（`.panel` / `.field` / `.result-section` / 打印样式）：

- **输入屏**：一句话描述 + 示例 + 12 个预设模板（按 10 个分类入口浏览，可展开看完整八项内容）。`?idea=一句话想法` 预填，加 `&start=1` 直接进入需求确认；`?preset=预设ID` 直接带预设起稿。
- **需求确认**：字段可逐个修改，并逐项标注「已识别 / 预设 / 假设」；最多 3 个问题，带可点选的答案；另设「特殊要求 / 补充说明」。
- **方案工作台**：左侧 12 模块导航（重点模块带圆点、滚动自动高亮），右侧完整内容；支持复制全文（Markdown）、复制招募文案、打印/存 PDF、收藏、单模块 AI 补充。预算金额可直接改，改后自动重算合计与占比。
- **方案记录**：最近方案、收藏与历史，保存在本机。

## 预设与分类

10 个分类入口：校园教育、体育竞技、公益志愿、商业商务、文化娱乐、社区社会、科技创新、会议论坛、节庆庆典、自定义。
12 个预设：新生迎新、学术讲座、创新创业比赛、体育赛事、公益志愿、环保宣传、商务交流会议、音乐节与文艺演出、招聘与职业交流会、科普教育、社区文化节、企业年会与颁奖典礼。

每个预设自带：场景介绍、适用人群、预设目标、推荐流程、人员配置、物资需求、预算结构、特有风险与特色环节。
数据在 `src/data/presets.ts`，界面与引擎都不认识具体预设。

**覆盖顺序**：族默认（`knowledge.ts`）← 类型覆盖（`CATEGORY_KNOWLEDGE`）← 预设覆盖（`presets.ts`）。
预设提供的流程、角色、物资、预算与风险会整体替换对应部分，所以不同预设生成的方案在结构上就不同，不是改个名字。

### 新增一个预设

```ts
// src/data/presets.ts
{
  id: 'preset-hackathon',
  name: '48 小时黑客松',
  group: 'tech',
  categoryId: 'startup-contest',
  tagline: '把想法在两天内做成可演示的原型',
  intro: '……（场景介绍，2–3 句，说明这类活动真正的难点）',
  audience: '开发者、设计师与产品经理',
  goal: '产出可演示的原型，并沉淀可继续孵化的团队',
  people: 120, budget: 40000, duration: 600,
  venue: 'indoor-large',
  flow: [{ name: '签到与组队', share: 0.2, detail: '……' }],
  roles: [{ role: '赛事负责人', fixed: 1, perPeople: 0, min: 1, max: 2, duty: '……' }],
  materials: ['工位', '电源', '网络'],
  budgetLines: [{ category: '餐饮', item: '三餐与夜宵', ratio: 0.3, note: '按 3 天备餐' }],
  risks: [{ title: '网络中断', cause: '……', likelihood: 2, impact: 3, mitigation: '……', contingency: '……', owner: '技术保障' }],
  highlights: ['通宵开发氛围', '评委现场体验'],
}
```

加完即出现在对应分类下，点击即可起稿；若想让它成为独立类型，再按上一节加 `CATEGORIES` 记录。

### 预设的修改、删除与补充

- **修改**：进入需求确认后所有字段可直接改，来源标记会变成「已填写」。
- **删除**：「清除预设内容」解除预设关联，把预设带入的字段退回该类型默认值（日期与类型保留）。
- **补充**：「特殊要求 / 补充说明」会进入方案的基本信息；也可以换类型，换类型后预设自动失效。

### 判断不出类型时

自由描述匹配不到关键词时，`brief.sources.category` 保持 `assumed`，需求页顶部出现类型询问（6 个快捷类型 + 全部 36 个类型 + 「继续用通用框架」），不会静默套用某个模板。

## 执行与修改

生成的不是介绍文章，而是可下发的执行文档：

- **六阶段时间轴**：筹备 → 宣传招募 → 前期检查 → 正式执行 → 收尾 → 总结。每条任务带负责人、完成时间（按活动日期换算成真实日期）、所需资源；负责人从本场真实岗位中映射，不会出现活动里没有的岗位。阶段差异写在 `src/data/phases.ts` 的 `FAMILY_TASKS`。
- **任务分工表**：岗位 / 层级（决策、策划与内容、传播与外联、执行与保障）/ 人数 / 职责 / 配置依据（每 N 人配 1 名）。人数随规模与预设变化。
- **预算清单**：细科目映射到 8 个标准类别（场地、设备、物资、人员、宣传、交通、餐饮、应急备用金），给出分类小计与总预算；金额一律标注「估算值，不是供应商报价」。预算与规模明显不匹配时会给出合理性提示。
- **物资清单**：名称 / 数量估算 / 用途 / 采购优先级（高·中·低）/ 负责人。
- **风险与应急**：风险描述、可能性、影响、等级、预防措施、应急方案、责任人；户外、大型、涉及未成年人或公共区域时自动追加风险，并展开「安全与合规强化」。
- **效果评估**：到场人数、报名转化率、现场参与度、满意度、活动完成率、实际成果，再叠加族级指标。
- **一句话修改**：方案页顶部输入「预算压缩到 5000 元 / 人数增加到 300 人 / 时间缩短到半天 / 改为室外 / 增加互动环节 / 减少工作人员」，解析为需求变更后重新生成，并回显「已应用 + 连带调整」。本地规则听不懂时，若配置了 Key 会交给 AI 解析成结构化补丁；仍无法识别会明确说明，而不是猜。
- **表格可编辑**：执行任务、风险、物资等表格点「编辑表格」即可逐格修改、删行、加行，修改即时保存到本机，打印与导出使用当前内容。
- **导出**：复制全文、打印 / 存 PDF（A4 横向，宽表可读）、下载 Markdown。

## AI 协同

- 无 Key：全部本地生成，AI 入口自动降级并提示。
- 有 Key：`/api/ai/assist` 支持三种模式
  - `clarify`：补充追问（问题必须落在 8 个字段白名单内）
  - `enrich`：为单个模块补 3–6 条建议，采用后才写入方案
  - `revise`：把自然语言修改要求解析为结构化补丁（预算/人数/时长/场地/人员系数/互动/安全），只在本地规则无法识别时兜底
- 服务端 `server/ai.mjs` 负责长度、枚举、数量收敛；预算、人数、议程等仍由本地引擎决定，AI 不能改写计算结果。

Key 的三种来源：页面「设置」（仅存本机 localStorage）、`.env.local` 的 `DEEPSEEK_API_KEY`、请求头 `X-DeepSeek-API-Key`。不要把 Key 提交到仓库。

## 本地数据

`event-planner-v2` 存最近方案、收藏与历史（最多 30 条），仅在本浏览器。v1 的旧数据（`activity-lab-v1`）不迁移。

## 已知限制

- 预算与用量均为估算，不含实时询价；活动库中的价格为演示值。
- 议程为单日模板，多日活动只给安排要点，不逐日排程。
- 天气、报批等合规提示与地区有关，执行前需按当地规定确认。
- AI 输出经过结构与长度校验，但不保证内容完全正确，采用前请自行判断。
