# 活动实验室 · 通用活动策划平台

一句话描述活动 → 需求理解与澄清 → 生成含 12 个模块的可执行方案。
覆盖校园、学术、体育、公益、商业、创业、文艺、教育、招聘、社交与通用场景；未预设的活动类型也会走同一套框架生成，而不是套模板。

基本流程完全离线可用；统一 AI 服务只作为「补充建议 / 追问」的增强层，需要网络与 API Key。

## 启动

建议 Node.js 24（本项目在 24 / 26 上验证）。

```bash
npm install
npm run dev     # 前端 5173 + AI 代理 8787
```

其他脚本：

```bash
npm test        # vitest（前端规则）+ node --test（服务端）
npm run build   # tsc + vite build
npm start       # 生产模式：托管 dist 并提供 /api
```

## 架构

```
配置层  src/data/taxonomy.ts    27 类活动 / 11 大类族 / 12 模块权重
        src/data/knowledge.ts   族级知识（议程·预算结构·角色·风险·KPI·渠道·合规）
                                + 类型级覆盖（只写差异）
引擎层  src/rules/intake.ts     自由文本 → 结构化需求 + 缺口提问 + 显式假设
        src/rules/generator.ts  需求 + 配置 → 12 模块方案（纯函数）
        src/rules/budget.ts     预算按结构切分，分项之和恒等于总额
        src/rules/export.ts     Markdown / 招募文案导出
表现层  src/App.tsx             输入屏 / 方案工作台
        src/components/*        BriefPanel、PlanView、BlockView、AiAssist…
服务端  server/index.mjs        静态托管 + /api/ai/*
```

**核心约束：引擎不认识任何具体活动类型。** 所有差异都来自配置，新增类型不需要改 `generator.ts`。

### 新增一种活动

1. 在 `src/data/taxonomy.ts` 的 `CATEGORIES` 里加一条：

```ts
{
  id: 'community-market',
  label: '社区市集',
  family: 'charity',            // 决定默认议程/预算/角色/风险
  keywords: ['市集', '跳蚤市场', '集市'],
  summary: '摊位、动线与邻里参与是重点',
  defaultPeople: 300, defaultBudget: 8000,
  defaultDuration: 240, defaultVenue: 'outdoor',
  defaultAudience: '社区居民与摊主',
  emphasis: { logistics: 'key', program: 'key' },  // 覆盖族默认权重
}
```

2. （可选）在 `src/data/knowledge.ts` 的 `CATEGORY_KNOWLEDGE` 里只写和族默认不一样的部分：
`agenda`、`budget`、`roles`、`risks`、`kpis`、`resources`、`interactions`、`notes`。

改完即可用，界面下拉、识别关键词、权重与全部 12 个模块自动生效。

### 模块权重

`key` 重点（内容全量 + 重点提示）、`normal` 常规、`brief` 简要（只留最关键两块，时间线/预算/人员表不裁剪）。
界面按权重显示徽标，侧栏高亮重点模块。

### 需求理解与假设

`intake.ts` 从文本里抽取人数、预算、日期、时长、场地、类型、人群与目标；缺失项用同类活动的常见值填充，并写入 `brief.assumptions`，界面逐条标注「假设」。
只对仍为假设的关键字段提问，优先级：人数 → 预算 → 日期 → 时长 → 场地 → 目标，每轮最多 3 个问题。

## 界面

两屏结构，视觉与组件沿用原有设计系统（`.panel` / `.field` / `.result-section` / 打印样式）：

- **输入屏**：一句话描述 + 示例 + 12 个预设模板（按 10 个分类入口浏览，可展开看完整八项内容）。`?idea=一句话想法` 预填，加 `&start=1` 直接进入需求确认；`?preset=预设ID` 直接带预设起稿。
- **需求确认**：字段可逐个修改，并逐项标注「已识别 / 预设 / 假设」；最多 3 个问题，带可点选的答案；另设「特殊要求 / 补充说明」。
- **方案工作台**：左侧 12 模块导航（重点模块带圆点、滚动自动高亮），右侧完整内容；支持复制全文（Markdown）、复制招募文案、打印/存 PDF、收藏、单模块 AI 补充。预算金额可直接改，改后自动重算合计与占比。
- **方案记录**：最近方案、收藏与历史，保存在本机。

## 预设与分类

10 个分类入口：校园教育、体育竞技、公益志愿、商业商务、文化娱乐、社区社会、科技创新、会议论坛、节庆庆典、自定义。
12 个预设：新生迎新、学术讲座、创新创业比赛、体育赛事、公益志愿、环保宣传、商务交流会议、音乐节与文艺演出、招聘与职业交流会、科普教育、社区文化节、企业年会与颁奖典礼。

每个预设自带：场景介绍、适用人群、预设目标、推荐流程、人员配置、物资需求、预算结构、特有风险与特色环节。
数据在 `src/data/presets.ts`，界面与引擎都不认识具体预设。

**覆盖顺序**：族默认（`knowledge.ts`）← 类型覆盖（`CATEGORY_KNOWLEDGE`）← 预设覆盖（`presets.ts`）。
预设提供的流程、角色、物资、预算与风险会整体替换对应部分，所以不同预设生成的方案在结构上就不同，不是改个名字。

### 新增一个预设

```ts
// src/data/presets.ts

  id: 'preset-hackathon',
  name: '48 小时黑客松',
  group: 'tech',
  categoryId: 'startup-contest',
  tagline: '把想法在两天内做成可演示的原型',
  intro: '……（场景介绍，2–3 句，说明这类活动真正的难点）',
  audience: '开发者、设计师与产品经理',
  goal: '产出可演示的原型，并沉淀可继续孵化的团队',
  people: 120, budget: 40000, duration: 600,
  venue: 'indoor-large',
  flow: [{ name: '签到与组队', share: 0.2, detail: '……' }],
  roles: [{ role: '赛事负责人', fixed: 1, perPeople: 0, min: 1, max: 2, duty: '……' }],
  materials: ['工位', '电源', '网络'],
  budgetLines: [{ category: '餐饮', item: '三餐与夜宵', ratio: 0.3, note: '按 3 天备餐' }],
  risks: [{ title: '网络中断', cause: '……', likelihood: 2, impact: 3, mitigation: '……', contingency: '……', owner: '技术保障' }],
```

加完即出现在对应分类下，点击即可起稿；若想让它成为独立类型，再按上一节加 `CATEGORIES` 记录。

### 预设的修改、删除与补充

- **修改**：进入需求确认后所有字段可直接改，来源标记会变成「已填写」。
- **删除**：「清除预设内容」解除预设关联，把预设带入的字段退回该类型默认值（日期与类型保留）。
- **补充**：「特殊要求 / 补充说明」会进入方案的基本信息；也可以换类型，换类型后预设自动失效。

### 判断不出类型时

自由描述匹配不到关键词时，`brief.sources.category` 保持 `assumed`，需求页顶部出现类型询问（6 个快捷类型 + 全部 36 个类型 + 「继续用通用框架」），不会静默套用某个模板。

## 执行与修改

生成的不是介绍文章，而是可下发的执行文档：

- **六阶段时间轴**：筹备 → 宣传招募 → 前期检查 → 正式执行 → 收尾 → 总结。每条任务带负责人、完成时间（按活动日期换算成真实日期）、所需资源；负责人从本场真实岗位中映射，不会出现活动里没有的岗位。阶段差异写在 `src/data/phases.ts` 的 `FAMILY_TASKS`。
- **任务分工表**：岗位 / 层级（决策、策划与内容、传播与外联、执行与保障）/ 人数 / 职责 / 配置依据（每 N 人配 1 名）。人数随规模与预设变化。
- **预算清单**：细科目映射到 8 个标准类别（场地、设备、物资、人员、宣传、交通、餐饮、应急备用金），给出分类小计与总预算；金额一律标注「估算值，不是供应商报价」。预算与规模明显不匹配时会给出合理性提示。
- **物资清单**：名称 / 数量估算 / 用途 / 采购优先级（高·中·低）/ 负责人。
- **风险与应急**：风险描述、可能性、影响、等级、预防措施、应急方案、责任人；户外、大型、涉及未成年人或公共区域时自动追加风险，并展开「安全与合规强化」。
- **效果评估**：到场人数、报名转化率、现场参与度、满意度、活动完成率、实际成果，再叠加族级指标。
- **一句话修改**：方案页顶部输入「预算压缩到 5000 元 / 人数增加到 300 人 / 时间缩短到半天 / 改为室外 / 增加互动环节 / 减少工作人员」，解析为需求变更后重新生成，并回显「已应用 + 连带调整」。本地规则听不懂时，若配置了 Key 会交给 AI 解析成结构化补丁；仍无法识别会明确说明，而不是猜。
- **表格可编辑**：执行任务、风险、物资等表格点「编辑表格」即可逐格修改、删行、加行，修改即时保存到本机，打印与导出使用当前内容。
- **导出**：复制全文、打印 / 存 PDF（A4 横向，宽表可读）、下载 Markdown。

## AI 协同

- 无 Key：全部本地生成，AI 入口自动降级并提示。
- 有 Key：`/api/ai/assist` 支持三种模式
  - `clarify`：补充追问（问题必须落在 8 个字段白名单内）
  - `enrich`：为单个模块补 3–6 条建议，采用后才写入方案
  - `revise`：把自然语言修改要求解析为结构化补丁（预算/人数/时长/场地/人员系数/互动/安全），只在本地规则无法识别时兜底
- 服务端 `server/ai.mjs` 负责长度、枚举、数量收敛；预算、人数、议程等仍由本地引擎决定，AI 不能改写计算结果。

Key 统一由后端管理：推荐 `.env.local` 的 `AI_API_KEY`（兼容 `DEEPSEEK_API_KEY`），也支持设置页提交到服务端内存的临时会话密钥。旧浏览器 localStorage 密钥自动移除，不再接受业务请求中的密钥头。临时配置提交本身仍可在本机开发者工具中看到；后续业务请求不带密钥。不要把 Key 提交到仓库。

## 本地数据

活动项目、原始附件、对话和版本使用 IndexedDB（`activity-projects-v1`）保存；旧的 `event-planner-v2` 记录首次打开时迁移，不覆盖同 ID 的已有项目。v1 的旧数据（`activity-lab-v1`）不迁移。数据属于当前浏览器和站点地址，建议定期下载完整备份；清除浏览器数据可能导致丢失，当前没有云同步。

## 已知限制

- 预算与用量均为估算，不含实时询价；活动库中的价格为演示值。
- 议程为单日模板，多日活动只给安排要点，不逐日排程。
- 天气、报批等合规提示与地区有关，执行前需按当地规定确认。
- AI 输出经过结构与长度校验，但不保证内容完全正确，采用前请自行判断。


## 方案编辑与突发调整

方案顶部「修改方案内容」开启编辑模式，各模块支持文字、流程、岗位、指标与表格的增删改，预算金额可直接修改。修改自动保存在本浏览器，打印和 Markdown 导出使用当前内容。手动改文字不会自动重算关联数字；需要联动重算时使用「修改基础需求」或「用一句话修改方案」。一句话修改先进入助手预览，确认选择的字段后才写入。默认保留手动编辑的章节；需要替换时必须单独勾选。调整版本可在助手历史中撤销，后续存在编辑时会提示先备份。

「突发情况调整」支持降雨/高温、场地不可用、工作人员缺席、设备故障与嘉宾迟到/流程延误。先预览，再应用，应急安排追加到活动内容、执行安排和风险管理，保留已有编辑。可以填写现场补充、继续编辑应急条目，并在当前页面撤销上次调整（刷新后撤销快照不保留）。

首页默认展示全部 12 个预设，仍可按 10 类筛选。类型无法识别时需要先选择类型或确认使用通用框架。清除预设保留用户主动修改和补充的字段。


## 活动项目、资料与动态调整

- 首页保留原纸张背景、插画与绿色风格，欢迎页进入现有活动选择；“我的活动”支持恢复草稿、继续编辑、复制、归档及确认删除。
- 方案可“逐行编辑本章”或“逐行编辑整份方案”，包括文字、清单、时间轴、岗位、指标、表格及预算行；原有预设仍可直接采用。方案名称、简介和章节标题也可修改。
- 方案顶部可提交组织者思路文件（TXT / Markdown / PDF / DOCX），保存原文件与补充说明。`OrganizerIdeaAdapter` 是未来转换接口，`POST /api/ideas/convert` 当前返回 501；不会声称已解析或已用 AI 转换。
- 资料中心保存本地原文件，CSV / XLSX 支持预览、选择表头、字段映射、问题检查，再确认追加；名单和支出不因 AI 调整而重写。PDF / 图片可预览，DOCX / XLS 目前仅保存与下载。
- 经费统计基于实际支出记录，区别预算、计划金额和已支出；空数据不生成虚构统计。
- 助手区分“本地规则预览”和“模型建议”。修改先预览、逐项选择后确认；手工编辑默认保留。源数据驱动未编辑文档同步，已手工编辑或 AI 起草的文档仅提示需要核对。
- 完整备份包含活动数据与原始附件，导入时恢复为新副本。存储失败会明确显示，不能替代浏览器外部备份。

模型调整接口为 `POST /api/assistant/adjust`，状态为 `GET /api/assistant/status`。服务端统一使用 `AI_API_KEY`（兼容 `DEEPSEEK_API_KEY`），支持 `AI_BASE_URL`（兼容根地址或 Chat Completions 完整端点）和 `AI_MODEL`；所有模块共用设置中心的非密钥配置。没有 Key 时模型入口显示未配置，本地规则仍可使用。上下文仅自动发送活动基础信息和汇总数字，不自动发送原始附件或完整名单；对话输入内容本身仍会发送给所选模型。

实现入口：`src/projects/`（项目与备份）、`src/materials/`（上传与导入）、`src/assistant/`（建议与版本）、`src/rules/editPlan.ts`（逐行编辑）、`server/assistant-ai.mjs`（模型代理）。

## 活动仿真实验室（本地概率模型）

工作台「活动模拟」为可选模块。先确认任务、人数、岗位、资源以及模拟假设，再开始实验；原有首页、植物纸张背景、图片、导航与策划功能继续保留。

- `src/simulation/model.ts`：只读输入快照、运行状态与实验记录；项目的可选 `simulationRuns` 字段兼容旧存档，IndexedDB 存储结构不变。
- `random.ts`：显式状态 PRNG、伯努利、泊松、正态与对数正态抽样。同一快照、参数、种子和操作次序可复现；分批推进不改变随机序列。
- `scenarios.ts`：九类场景的设备、区域、停留时间、物资/设备依赖与相对风险权重。所有默认概率和场景系数为演示假设，未经过现实样本校准。
- `engine.ts`：1分钟时间步、到场队列、随机服务完成、有限容量、工作人员分配、场地互斥、前置任务、随机故障及费用。天气只在户外适用，设备故障只在设备相关任务进行时适用；允许全程无突发事件。多日活动仅取首日，最多1440分钟计划，最多20000名参与者；超时明确显示未完成。
- `Sandbox.tsx`：SVG 二维场景。人物为按人数比例聚合的标记，图例明确每点代表人数；排队、最近人员流动、设备、场地关闭均从引擎状态派生，无独立随机动画，不需要3D或新增绘图库。
- `SimulationLab.tsx`：准备度与参数确认、开始/暂停/单步/速度控制、有限备用资源决策、任务表、事件因果记录、复盘、保存/恢复和JSON下载。实验最多保留5条，并纳入完整项目备份。

结果费用为预算80%随任务完成计提加模拟额外费用，不是已支出财务记录。延误、排队均为该次假设实验结果。敏感性分析每组20次，比较事件强度0.5/1/2倍，保持同一组种子；经验P50/P90不等于现实置信区间。当前不支持历史数据自动拟合、经验分布导入或真实场地导航网格。

建议只有在组织者勾选并确认时，才追加到正式方案风险章节，并保留撤销版本。模拟中的预算、名单、成绩和人员配置从不自动写入真实源数据。正式方案或资料变化后，旧快照继续可查看，但需重新模拟才能应用建议。模型源标签和数据依据由组织者填写；引擎没有伪造AI调用。


## 产品级生命周期升级（2026-11-05）

- 工作台五个主分区：概览、策划、智能分析、模拟与执行、复盘。原工具箱、资料、文档、名单与统计收纳在策划子导航，原始背景/图片资源保持不变。
- `#settings`：外观、统一 AI、使用偏好、数据与隐私。自然绿/蓝/米色/深色，字号、内置原图、覆盖层、动画、引导和提醒持久化。
- `server/ai-service.mjs` 是唯一供应商配置与请求出口。服务端请求有超时、有限 502/503/504 重试、取消、状态记录与错误分类。非密钥配置保存在 Git 忽略的 `ai-config.local`；密钥只在环境变量或进程内存。面向本机单用户，不是公开多租户服务。
- `src/lifecycle/health.ts`：确定性时间/人员/预算/容量/物资/应急/依赖检查。展示通过项数和依据，不把它包装成安全评分。
- 命名版本、恢复前自动快照、内容比较、每方案 20 次共同随机种子的蒙特卡洛比较；显示按时完成、超预算、平均延误、人员利用率和风险次数。使用假设模型，非真实风险预测。
- 人员任务共享原 `tasks` 表；按技能、可用截止日、优先级和负载提出本地建议，确认后应用。报名共享 `registrations`，独立 `checkin` 字段保留原报名状态；本机扫码枪/粘贴个人二维码内容后确认签到，二维码不含姓名/联系方式。
- 采购共享 `expenses`，方案预算行关联到采购记录；实际支出不被方案变化覆盖。应急预案、真实事件、复盘及确认案例保存在可兼容的工作台表中。文档复用现有 Word/Excel/PDF 导出并保留过期检查。
- 二维码使用 [node-qrcode](https://github.com/soldair/node-qrcode) 的本地浏览器生成接口，不调用远程二维码图片服务。

### 已知边界

尚无账户权限系统、云数据库、跨设备实时任务同步和公众手机自助报名/签到；现场数据为本机人工记录。自定义背景上传未开放，内置背景和覆盖层可用。人员分工是可解释的启发式建议，不保证最优排班。体检不替代专业安全审核。未提供真实模型密钥时，不宣称已完成真实供应商连通性验证。

详细分阶段交付与验证见 `docs/lifecycle-upgrade.md`。
