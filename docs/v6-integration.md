# V6 策划器与 3D 游戏整合

主项目 `npm run build` 先编译 `game/`，再把游戏放入 `dist/play3d/`。本地开发时先执行一次构建，主站的 `/play3d/index.html` 即可访问游戏。原 `EventSimulator3D` 文件夹未修改；`game/` 是整合时复制的当前开发版本，后续应以主项目副本为准。

策划器仍使用 IndexedDB 保存正式活动；游戏继续使用原有存档键保存可编辑场景。`src/integration/gameBridge.ts` 从活动项目和唯一的 `PRESETS` 注册表发布版本化只读快照到同源浏览器存储。游戏按活动 ID 导入，不修改策划案；场景拥有自己的 ID。模拟结束后，游戏将关联活动 ID、场景 ID 的结果写入独立记录，策划器的“模拟记录”可查看预算差额、到场、延误和事件。

此同步只适用于同一浏览器、同一站点来源；它不是云同步。游戏入口会刷新策划快照。再次导入时若项目更新时间变化，游戏显示同步提示并允许保留旧场景。未填信息在游戏中使用现有演示默认值，导入页会提示。游戏运行不依赖 AI 密钥。

已知限制：场景设施目前按活动类型和推荐场地初始化，59 个预设共用类型层的设施规则，尚无逐模板的专属 3D 道具；游戏结果保存在同源浏览器存储，尚未写入策划器 IndexedDB；工作组名称已传递，组员岗位细节还未映射到逐个虚拟人物。
